# Переходы между страницами: View Transitions API

Между роутами (лендинг ↔ `/certificates` ↔ `/stats`) нужен красивый современный
переход. Все решения ниже — итог гриллинга; этот ADR — контракт для реализации.

## Решения

- **Механизм: View Transitions API через `withViewTransitions()` в
  `provideRouter`, а не `@angular/animations`.** Браузер сам делает снапшоты
  старой и новой страницы, вся анимация — чистый CSS на
  `::view-transition-old/new(root)` в `styles.css`. Ноль зависимостей,
  дружит с zoneless; браузер без поддержки просто переключает страницу
  мгновенно. Классические роут-анимации отклонены: лишний пакет и wrapper
  вокруг `router-outlet` без выигрыша для нашего случая.
- **Характер: crossfade с лёгким подъёмом.** Старая страница уходит в
  `opacity: 0` за 200 мс, новая появляется с `translateY(12px) → 0` за 300 мс
  с easing из motion-сигнатуры `[data-reveal]`. Shared-element переходы
  осознанно отложены: базу они не меняют, добавить можно точечно позже.
- **Якорные навигации не анимируются.** Роутер запускает transition на любую
  навигацию, включая клик по `#section` в шапке — лендинг «моргал» бы при
  каждом скролле по меню. Политика живёт в `src/app/view-transition-policy.ts`
  (composition-root логика, не фича): `shouldSkipViewTransition` сравнивает
  пути from/to без fragment, при совпадении вызывается
  `transition.skipTransition()`. Параметры типизированы структурным
  `RouteSnapshotNode`, чтобы спек не строил настоящие снапшоты роутера.
  Первая загрузка тоже без анимации (`skipInitialTransition`).
- **`prefers-reduced-motion: reduce` гасит переход полностью** — мгновенное
  переключение, как до появления переходов. Консистентно с тем, как проект
  уже обрабатывает остальную анимацию (`styles.css`).

## Тестирование

Спек `view-transition-policy.spec.ts` покрывает политику (якорь → skip, смена
роута → animate) и извлечение пути из снапшота. Сам факт отрисовки анимации —
работа браузера, в тестах не проверяется; регрессионным щитом служит
существующий `e2e/navigation.spec.ts`.
