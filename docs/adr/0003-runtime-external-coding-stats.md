# Рантайм-статистика с внешних платформ: failover-цепочка, TTL-кэш, unavailable как состояние

Страница `/stats` показывает статистику с алгоритмических платформ (LeetCode,
Codeforces, Codewars). Это первая фича, которая ходит в сеть в рантайме: до неё
весь контент был типизированными TS-модулями, проверяемыми на этапе сборки.
Все решения ниже — итог гриллинга; этот ADR — контракт для реализации.

## Решения

- **Доставка: клиентский fetch в рантайме, а не cron-снапшот в репо.**
  GitHub Pages — статика, бэкенда нет. Вариант «GitHub Actions cron → коммит
  JSON → ребилд» отклонён: пользователь явно выбрал живые запросы с красивой
  деградацией. Следствие: недоступность данных — нормальное состояние UI,
  а не ошибка сборки (как `RepositorySnapshot` может отсутствовать).
- **LeetCode — через цепочку публичных прокси-API с failover.** Официальный
  GraphQL LeetCode закрыт CORS'ом, поэтому ходим через alfa-leetcode-api
  (публичный инстанс). Цепочка — `FailoverCodingStatsSource` в infrastructure:
  последовательный обход адаптеров, первый успех возвращается, полный провал —
  `AllSourcesUnavailable` с перечнем попыток. Каждый адаптер нормализует ответ
  в единый DTO, поэтому члены цепочки взаимозаменяемы. Источник, не покрывающий
  обязательные поля (разбивка easy/medium/hard), в цепочку не входит:
  leetcode-rest-api не добавлен, пока форма его ответа не проверена.
- **Codeforces и Codewars — напрямую, их официальные API открыты по CORS.**
- **Таймаут 45 с на источник через AbortController.** Браузерный fetch не
  таймаутится сам, а повисший сокет заблокировал бы failover навсегда. 45 с
  покрывает холодный старт засыпающего Render-инстанса. UI при этом не
  блокируется: `resource()` оставляет страницу интерактивной, карточка честно
  пишет, что сервис просыпается.
- **Кэш: localStorage, TTL 60 минут, stale-while-revalidate.** Свежий кэш
  отдаётся без сети; просроченный рендерится сразу с пометкой «кэшированная
  копия» и фоновым рефрешем (инвалидация + `resource.reload()`); промах идёт в
  сеть. У публичного инстанса общий rate limit — кэш ещё и вежливость. Кэш
  платформенный: падение одного источника не инвалидирует остальные.
- **Кэш — доменный порт `StatsCache`, адаптер — localStorage.** Адаптер
  переживает отсутствие storage (пререндер), битый JSON и чужую схему — всё
  читается как промах; при чтении значение повторно валидируется доменной
  фабрикой `codingProfile.create`.
- **Оркестрация — use case `LoadCodingStats` в application**, поверх портов
  `CodingStatsSource` (failover-композит) и `StatsCache`. Стор держит по
  `resource()` на платформу — состояния независимы, outage одной платформы не
  прячет остальные. Наружу — CQS: `GetCodingStatsHandler` (query → сигнал
  вью) и `RefreshCodingStatsHandler` (command → форс-рефреш), презентация
  видит только их.
- **Домен — union фактов, а не плоская структура.** Рейтинги несовместимы
  (Codeforces Эло, Codewars kyu, LeetCode contest rating), поэтому общее
  ядро `CodingProfile` — platform/handle/profileUrl/fetchedAt/totalSolved,
  а специфика — дискриминированный union `PlatformFacts` (как `ContactChannel`).
  Инвариант LeetCode: `totalSolved = easy + medium + hard`, проверяется при
  парсе — донат и полоски питаются от одних чисел и не могут разъехаться.

## Последствия

- e2e никогда не ходят в реальные API: Playwright `page.route()` отдаёт
  фикстуры и моделирует падение источников.
- Фикстуры мапперов (`infrastructure/content/fixtures/`) фиксируют контракт
  API; осознанное обновление фикстуры — способ заметить тихую смену формата.
- GitHub-статистика (коммиты и т.п.) добавляется как четвёртый член union'а
  и адаптер, без изменения модели.
