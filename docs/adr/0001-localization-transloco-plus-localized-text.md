# Локализация: Transloco для UI, LocalizedText для контента

Лендинг имеет две локали (en, ru). Локализация разделена на две части с разными
инструментами: тексты обвязки UI (кнопки, навигация, plural-формы) идут через Transloco
(runtime-словари, сигналы), а контент резюме хранится в домене как `LocalizedText
{ en, ru }` — VO из `shared/kernel`, обе версии обязательны и лежат рядом в одном
контент-файле. Домен про переключение языка не знает: выбор текущей локали происходит
в UI-слое.

## Considered Options

- **`@angular/localize` (встроенный i18n)** — отклонён: compile-time подход требует
  отдельной сборки на локаль и извлекает строки из шаблонов, а наш контент живёт
  в TS-литералах за портом `ResumeRepository` — туда встроенный i18n не достаёт.
- **Отдельный контент-файл на локаль** (`content.en.ts` / `content.ru.ts`) — отклонён:
  версии неизбежно разъедутся молча; `LocalizedText` держит обе рядом, и спека «контент
  разбирается» проверяет обе.

## Consequences

- Любое текстовое поле контента типизируется `LocalizedText`, а не `NonEmptyString` —
  добавление третьей локали потребует расширения VO и всех контент-литералов.
- Plural-формы длительностей («1 год / 2 года / 5 лет») — забота Transloco
  (messageformat), домен отдаёт только числа.
- В домен и application-слой нельзя импортировать Transloco — это проверяется теми же
  архитектурными правилами, что и запрет Angular в домене.
